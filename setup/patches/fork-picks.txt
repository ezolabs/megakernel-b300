# fork-picks.txt — the redundancy scan's map of upstream PR picks, read by
# tools/fork-sync.sh's `sync`/`plan` redundancy scan alongside the branch's own
# `Cherry-picked-from-upstream-PR:` trailers. A trailer only exists on the commit that
# carries it, so a hand cherry-pick made without one, or one of several commits from a
# multi-commit PR that a hand-resolve forgot to tag (04-engine.md's PR #39154, second
# commit), is invisible to a trailer-only scan. This file's PR numbers are unioned with the
# trailer scan's before the `gh pr view` DROP check runs, so every pick gets checked whether
# or not its trailer survived.
#
# One line per picked commit, in the order picked:
#   <sha-prefix> #<PR> <subject-prefix>
# <sha-prefix> is the commit's short sha AT THE TIME IT WAS PICKED — it goes stale across a
# rebase (rebasing rewrites shas) and is kept only as an audit trail for a human reading this
# file, never re-resolved by the scan itself, which keys on the PR number alone.
# <subject-prefix> is the commit's own subject line (or its PR's title when the field wasn't
# available), for the same human-audit purpose.
#
# `fork-sync.sh pick <PR_NUMBER>` appends one line here per commit it applies, automatically,
# in the same run that adds the trailer.
